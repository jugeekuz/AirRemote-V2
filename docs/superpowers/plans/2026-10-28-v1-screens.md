> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Login, Sign up, Devices, Remotes and Remote details screens that look as close to V1 as possible and work end to end against the V2 backend (plus the endpoints they need: device online status and deletes).

**Architecture:** Follows `frontend/ARCHITECTURE.md` and the `frontend-*` skills (load the relevant skill before each kind of work: `frontend-feature`, `frontend-api`, `frontend-ui`, `frontend-state`, `frontend-testing`, `frontend-i18n`, `frontend-dev`). Backend changes follow root `CLAUDE.md` "Backend conventions".

**Tech Stack:** Existing stack plus `@react-navigation/bottom-tabs`, `lucide-react-native`, `expo-camera` (QR), `expo-font` + `@expo-google-fonts/poppins`, `expo-image` (images/SVG) as needed.

## Review Focus

1. **A command that never settles** (device unplugged mid-learn): polling must stop at `expired`/`failed`, show the Error dialog, and leave the UI idle — never spin forever. Pinned in Task 10.
2. **Pressing a button twice quickly / pressing while another press is pending**: one command per tap at most while pending; the control stays consistent. Pinned in Task 10.
3. **Deleting the device whose remote is open** (or a remote while its details are open): the details screen must not crash; it shows its not-found state or goes back. Pinned in Task 10.
4. **Scanning a QR code that isn't AirRemote's** (or a malformed MAC/code): the wizard says so and stays on the scan step. Pinned in Task 8.
5. **Session expiry while a screen polls** (refresh on 401 during learn/press polling): polling continues after the refresh; a refused refresh lands on Login without error dialogs piling up. Pinned in Tasks 1 and 10.
